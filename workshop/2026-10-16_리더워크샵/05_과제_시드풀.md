# 05. 시드 과제 풀 (벽에 붙일 예시 카드 10장)

> 리더가 템플릿을 비워 왔을 때 ‘입양’하는 카드입니다. 인쇄할 때는 **②핸들 노동과 ③목적지만 남기고** 나머지 칸은 비워 둡니다.
> `__`와 [추정]은 오너가 채울 값입니다. 엔터 OS는 1개월 범위 밖이라 파킹 랏 카드로만 둡니다.
> CRM 카드는 관계 담당 리더 자리에 미리 놓되 ‘다른 카드로 바꿔도 됩니다’ 메모를 붙입니다.

## 1. 더쇼 미팅 기록 자동 요약·CRM 저장·팔로업 알림 (B2B CRM DB화)

| 칸 | 내용 |
|---|---|

| ③ 목적지 | 담당자가 바쁘거나 바뀌어도 약속한 팔로업이 빠지지 않고, 영업 담당이 ‘이번 주 누구에게 연락할지’를 정한다. 관계 판단은 담당자가, 기록과 알림은 AI가 한다 |
| 현재 비용 | 미팅 1건당 기록·정리 __분 × 월 미팅 __건 [추정, 오너 확인]. 후속 관리 누락 건수는 현재 측정되지 않음 |
| ⑤ 데이터 | 담당자가 직접 남긴 3줄 메모(고객사명은 더미), 아티스트사 기본 정보(공개), 투어·앨범 일정(공개). 사내 서버 저장 원칙, 녹음과 실명 고객 정보는 쓰지 않는다 |

| ④ 완료 조건 3층 | 예/아니오: 메모 1건 입력 시 요약·다음 액션·팔로업 날짜가 시트 한 줄로 저장된다 / 팔로업 날짜 하루 전 슬랙 알림이 온다. 숫자: 샘플 10건 중 요약에서 핵심 합의사항 누락 __건 이하. 루브릭: '이 요약만 보고 다음 미팅을 준비할 수 있다' 1~3점 |
| 검증 방법 | 오너가 실제(마스킹) 미팅 메모 10건과 AI 요약을 나란히 대조하고, 알림은 테스트 날짜로 실제 수신 확인 |
| ⑦ 하루 MVP | MVP: 메모 텍스트 붙여넣기 → 요약·액션·날짜 추출 → 사내 시트 저장 → 슬랙 알림 1종. 전체 CRM 화면, 외부 SaaS 연동은 범위 밖 |
| 임팩트 | 대표 목표 (3) B2B CRM 사내 저장과 직접 연결, 미팅 후속 기록의 자산화. 근거로 쓰인 결정 = 주간 영업 우선순위 |
| 실현성 | 높음. 텍스트 입력 기준이면 하루 시연 가능. 데이터 보안 조건 확인이 관건 |
| 리스크 | 미팅 내용의 외부 전송 보안, 영업 담당의 디지털 툴 거부감, 요약이 뉘앙스(관계 온도)를 놓칠 위험 → 루브릭에 '관계 신호' 항목 추가 |

| 리스크 | 추측성 정보를 사실처럼 채우는 환각 → 출처 링크 필수 체크. 크롤링 이용약관 확인 필요 |

| 임팩트 | 반복 업무 감소 지표화(대표 목표 2)에 가장 직관적. 아티스트 등록 사례와 같은 패턴이라 학습 효과가 큼 |
| 실현성 | 높음. 입력 형식이 정해져 있어 판정이 쉬움 |
| 리스크 | 시간대·음력·변경 공지 처리 오류. '사람을 대체한다'로 읽힐 위험 → 업무 단계 언어로만 소개 |

## 5. 아티스트 등록 '남은 10%' 검증 루프

| 칸 | 내용 |
|---|---|
| 오너 팀 | 개발(균님 [이름 확인]) + 운영 |
| ② 핸들 노동 | AI가 채우지 못했거나 틀릴 수 있는 필드를 사람이 하나씩 찾아보고 고치는 단계 |
| ③ 목적지 | 어떤 필드가 왜 비었거나 의심스러운지 자동으로 표시되어, 검수자는 의심 건만 확인하고 등록 품질 기준이 문서로 남는다 |
| 현재 비용 | 등록 1건당 보완 __분 [추정, 균님 확인]. 약 90%의 분모(필드/건수)는 균님 확인값 사용 |
| ⑤ 데이터 | 기존 등록 결과와 수정 이력(사내), 공개 음원 플랫폼 정보(공개) |
| AI 활용 단계 | 4 개인 에이전트(+ 판정 루브릭) |
| ④ 완료 조건 3층 | 예/아니오: 각 등록 건에 필드별 '확신/의심/없음' 표시가 붙는다 / 의심 사유가 한 줄로 적힌다. 숫자: 정답이 있는 표본 30건에서 실제 오류의 __% 이상이 '의심'으로 걸러진다. 루브릭: '검수자가 의심 건만 보고 끝낼 수 있다' 1~3점 |
| 검증 방법 | 과거 사람이 수정한 이력을 정답으로 두고 탐지율 계산 |
| ⑦ 하루 MVP | MVP: 등록 결과 30건 → 필드별 의심 표시와 사유 → 검수 시트. 앱 반영 자동화는 범위 밖 |
| 임팩트 | '생산에서 검증으로'를 사내에서 직접 보여 주는 대표 사례. 검증 기준 자체가 자산 |
| 실현성 | 높음. 데이터와 정답 이력이 이미 있음 |
| 리스크 | 의심 표시가 과다하면 검수 부담이 오히려 늘어남 → 숫자 합격선에 '오탐 __건 이하' 추가 |

## 6. 마케팅 채널 데이터 통합·주간 인사이트 자동 요약

| 칸 | 내용 |
|---|---|

| ③ 목적지 | 월요일 오전 한 장의 요약으로 이번 주 콘텐츠·예산 배분을 결정한다(성공 지표 = 근거로 쓰인 결정 수) |

| AI 활용 단계 | 3 자동화형 |
| ④ 완료 조건 3층 | 예/아니오: 지정 채널 전부의 지표가 한 시트에 모인다 / 요약이 정해진 시각에 슬랙에 게시된다. 숫자: 수기 집계 대비 수치 불일치 __건 이하. 루브릭: '이 요약으로 이번 주 결정 1개를 했다' 1~3점 |
| 검증 방법 | 오너가 지난주 수기 보고서와 자동 요약을 대조하고, 다음 주 회의에서 실제로 쓰였는지 기록 |
| ⑦ 하루 MVP | MVP: 내보내기 파일 3종 업로드 → 통합 시트 → 주간 요약 3줄 + 결정 제안 1개. API 자동 수집은 2차 |
| 임팩트 | 마케팅팀 최대 니즈. '결정에 쓰이지 않는 수집'을 끊는 구조 |
| 실현성 | 중상. 파일 업로드 방식이면 하루 가능, API 연동은 권한 확인 필요 |
| 리스크 | 채널별 지표 정의 불일치, 수집만 늘고 결정에 안 쓰이는 함정 → 루브릭으로 방어 |
